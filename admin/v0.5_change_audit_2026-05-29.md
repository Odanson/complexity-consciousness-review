**Question being answered:** *Did v0.5 accidentally drift?*
**Short answer:** **No methodological drift.** All substantive protocol logic — search, screening, extraction, taxonomy, synthesis — is preserved unchanged. Two **framing / wording** items warrant correction before OSF upload (both are flagged in §4 below).

---

## 1. Audit methodology

For each edit between v0.4.4 and v0.5 I classify the change as one of three categories:

- **Administrative** — metadata, version bumps, ORCIDs, affiliations, dates, pointers, project-management items.
- **Wording-only** — tightens or restates existing claims; does not change the underlying scientific or methodological content.
- **Methodological** — changes search, screening, extraction, taxonomy, synthesis, or any pre-registered decision rule.

I then flag explicitly anything that:

- changes **scientific interpretation** (claims, scope, framing of what the review can warrant),
- changes **execution logic** (workflow, sequencing, dependencies),
- risks **protocol drift** (silent accumulation of small changes that, in aggregate, alter the registered design).

## 4. Findings — what needs attention before OSF upload

**v0.5 is methodologically clean.** Search, screening (including the v0.4.4 Elicit deployment), extraction, taxonomy, and synthesis are unchanged. The only items that warrant edits before OSF upload are framing / wording / data-fill items:

1. **§C decision 8 — reframe the Jürgen-feedback record.** The current "Resolved … Declined" wording overstates the closure. Reframe as **"Considered; not implemented as a v0.5 protocol change; to be evaluated empirically post-search."** Add a light *Monitoring plan* paragraph naming the post-search term-level contribution analysis as the empirical mechanism. The underlying methodology (locked Block 2, Lucia-driven expansion, seed-miss recoverability via §B5 citation tracking) is unchanged; only the tone changes.

2. **§B1 milestone schedule — three-stage cadence.** Replace the single "First supervisor milestone — end of July 2026" row with a three-checkpoint schedule:
   - **Late June 2026** — operational checkpoint (multi-database search executed and locked; dedup corpus available; screening pipeline operational).
   - **Late July 2026** — substantive scientific checkpoint (bulk screening progressing; preliminary corpus characterisation; early Axis-1 mapping on includes-so-far).
   - **Aug / Sept 2026 →** — synthesis and manuscript trajectory.

3. **§B1.2 — fill the three remaining affiliations** (Samson, Andrej, Jürgen) with the verbatim strings supplied in the user's 2026-05-29 PM message.

4. **§B14 funding line — drop the "(to confirm)" placeholder.** Now confirmed via Samson's affiliation entry which includes Max Planck School of Cognition.

5. **§B6.3 Search audit trail — add a one-line execution-philosophy note.** The protocol does not currently state that search execution is manual via each database's web interface (rather than coded API calls). Adding one sentence here clarifies the execution model and aligns the protocol with the operational reality just confirmed with the librarian; this is **documentation of an existing intention**, not a methodology change.

6. **`docs/data_management_plan.md` §7 Costs — neutral wording.** Replace the personal-subscription line with the user-supplied wording: *"access to required software and services will be maintained for the duration of screening."*

7. **`rayyan_reevaluation.md` — conservative recommendation.** Soften the recommendation to keep Rayyan in the protocol "lightly" for deduplication and screening management where appropriate; do *not* recommend removing it from §B7. This is a non-protocol document so the change is purely advisory.

8. **`README.md` status table — reflect infrastructure progress.** Add (or update) rows for OSF workspace status (private, unregistered, populated-pending), database access (Scopus / WoS / PsycINFO / IEEE Xplore confirmed via MPI/CBS login; Embase pending), and search execution philosophy (manual UI execution; code restricted to downstream QC and analysis).

None of these changes affect the registered methodology. Items 1–6 are surgical edits to v0.5 of the protocol; items 7–8 are companion-document refinements.

## 5. Process improvements identified (for future versions)

- **Version-row consistency.** When bumping the header version line, also bump the §B1 administrative table row in the same commit (V2 above caught a stale v0.4.3 reference). Trivial but worth a standing item.
- **Editorial sweeps and version bumps in the same calendar day.** The wording-audit edits (W1–W3) and the v0.5 administrative bump both landed 2026-05-29; a diffed reader cannot tell from the file alone which were "editorial" and which were v0.5. The amendments log in v0.5 should reference both `wording_audit_2026-05-29.md` and the v0.5 changes so anyone diffing v0.4.4 vs v0.5 has the full attribution.
- **Pre-OSF-upload checklist.** A short pre-upload checklist (run change-audit; verify all placeholders filled; verify all cross-references resolve; verify no stale version refs) would have caught V2 and the §B1.2 placeholder situation before requiring this audit.

---

## 6. Bottom line

**v0.5 has not drifted.** It is v0.4.4 plus administrative metadata, project-management cadence, a decision record that explicitly documents a *non-change* to methodology, and an editorial wording sweep that strengthens precision without changing substance. The seven items in §4 above are surgical and can be applied in a single commit before OSF upload. After those are applied, the protocol is upload-ready.
